# Handdrawn visual rules

## 自动检查

- CJK 文本使用 Ma Shan Zheng（fontFamily 11），纯英文使用 Virgil（1）。
- 双语内容拆成 CJK/English 两行；边标签字号至少 32px。
- 标题位于顶部安全区（y >= 10）；节点文字留有内边距。
- 边标签、批注、装饰性线条和箭线不得遮住或穿过节点正文；如果节点编号和标题已经表达顺序，优先删减边标签。
- 箭头必须绑定起止节点，端点落在节点边界附近。
- 检查明显容器重叠、过小间距、悬空箭头、边标签是否覆盖可读文本，以及箭线是否穿过可读文本。
- sketch 输出必须有 `appState.sketchStyle` 与 `sketchTemplate`，不得把 prompt 或任务说明写入图中文字。

## 人工目检清单

渲染 PNG/SVG 后依次检查字体退化、文字溢出、双语层级、标题安全区、箭头是否穿过节点或正文、边标签是否压住正文、曲线是否表达语义、泳道/架构批注是否有留白，以及是否存在意外重叠。

## 内容地图排布

内容地图、概念闭环、机理地图不要用无序散点。推荐 `metadata.layout_pattern: "content-map-orbit"`：

- 主题节点放中心，但只作为“主题岛”，不承载主路径箭线。
- 8–12 个正文卡片沿外环顺时针排列；左侧放输入/数据源，底部放数据/模型底座，右侧放状态/推演，顶部放应用/决策，反馈节点靠近起点。
- 治理、可信度、验收点、安全等 guardrail 放底栏，不混进主环。
- 主环节点间至少留出手绘轮廓的呼吸空间；若文字框宽约 360px，横向相邻框建议留 60px 以上。
- 反馈线只在外环回到起点，不穿越中心主题岛。

## 闭环

`render → look → targeted fix → render`。只针对发现的问题做局部修正，再以 strict visual 校验和第二次字节比较确认确定性。

边界：当前 localhost:5001 本地 build 可能自动 fit 到顶部并被浮动工具栏覆盖；scene 的 `appState.scrollY` 与不可见 spacer 均未被该 build 尊重。正式视觉验收以 PNG/SVG 为准，编辑器内可手动平移画布。
